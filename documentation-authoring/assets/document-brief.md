# Document brief

Fill in only what the task has not yet made clear; cite complete existing inputs directly instead of asking again mechanically.

- Reader and post-reading goal: what to learn / do / look up / understand.
- Primary type: tutorial / how-to guide / reference / explanation; where supporting content is linked.
- Scope: what is included, what is explicitly excluded, applicable version/environment.
- Existing entry: document to modify, known anchors, currently confirmed structure and writer.
- Facts and terminology: location of authoritative source code/contracts/decisions, project glossary and style guide.
- Delivery: format, allowed destination, diagram/table needs, required rendering or readability checks.
- Existing approval: adopt the user-given outline and scope directly; record an approval point only when an applicable requirement explicitly exists.
- Structure: sections ordered by the reader's goal and the question each section answers.
- Missing items: which content is affected, what can continue, what evidence is needed.

The final body is self-contained; the brief and fact-checking process stay in the project-designated record location and are not mixed into a business README or the user's operating steps.
