# Skill design card template

The author fills this template into the task record; variables are legitimate fields to fill, not package body text. When an equivalent design exists, reference it directly; do not build another plan.

- Package/current version/mode: {{name, version, design or implementation}}
- User requirement and source: {{request location; author suggestions listed separately}}
- Target behaviour/artefact: {{given which input, which observable decision should be completed}}
- Trigger/adjacent exclusions: {{one normal request; one request with the same keywords that should not trigger}}
- Existing methods and overlap: {{which authority is reused; why an addition or change is still needed}}
- Inputs/missing items: {{required material, sources, what each missing item blocks}}
- Decision chain: {{evidence -> branch -> action -> failure recovery -> ending evidence}}
- Method and parameters: {{shared decisions; values supplied by consuming projects; old facts that must not move in}}
- Dual sources and conflicts: {{external pinned source, old material location, adopted/dropped, own-authored, undecided}}
- Candidate files and when they are read: {{purpose of body/topic pages/templates/scripts; no empty directories}}
- Three-mode boundary/sole writer: {{output scope this time and actions that cannot escalate automatically}}
- Verification: {{static, script fixtures, content walkthrough, real behaviour, composition, cross-project; expectation and missing conditions for each}}
- Resources and dependencies: {{recommended grade/reasoning, capability gaps, expected duration and escalation conditions}}
- Shared upgrade/recovery/licensing: {{consumers, version semantics, recovery point, notice retention}}
- Output and unverified: {{candidate location, actual evidence, what was not proven}}

A design card is not an approval record. The actual implementation scope references existing authorisation; without authorisation, deliver only the design.
